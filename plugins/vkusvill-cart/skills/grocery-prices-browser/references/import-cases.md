# Контрольные случаи импорта

## Назначение и границы

Это ожидаемые бизнес-результаты для ревью и серверных/UI-тестов; сами примеры **не являются доказательством исполнения панели**. Репозиторий содержит навыки, а не обработчик импорта. Проверка структуры примеров не исполняет расчёты, замену или идемпотентность на сервере.

[import-examples.json](import-examples.json) — массив из четырёх независимых примеров. Один элемент массива соответствует аргументам одного вызова `prices_browser_show`; весь файл целиком не передавать. Внутри payload нет метаданных теста и новых полей. Данные вымышлены, названия, ID, точки и URL главных страниц служат только проверке формы. Не отправлять их в живую панель как наблюдения, не считать ценами на сегодня. При реальной работе нужны стабильные ID, ссылки фактических карточек и настоящее время чтения.

| Элемент JSON (с 1) | Что проверяет | Ожидаемая трактовка |
| --- | --- | --- |
| 1 | Упаковка 1 л, обычные 109 ₽ | Цена полной упаковки; условные 103 ₽ только в пояснении, не в поле price |
| 2 | 900 мл, цена по карте 89 ₽ | `conditionsConfirmed=false`; исключить из подтверждённого итога |
| 3 | CAPTCHA | Только check, не пустой успешный поиск и не нулевая цена |
| 4 | 139 ₽/кг, минимум 1,5 кг | Ограничение представления при импорте; нет фиктивной упаковки или подтверждённого продукта |

## Ожидаемые бизнес-сценарии

| ID | Исходные данные / действие | Ожидаемый результат и защита |
| --- | --- | --- |
| B01 | Запрос 1 л молока; карточка указывает 930 г | Сохранить 0,93 кг, не 0,93 л. Не считать объём и требуемое число упаковок; не приравнивать к карточке 930 мл |
| B02 | 930 мл молока за 100 ₽; нужно 1 л | 0,93 л в упаковке; 2 упаковки, 1,86 л, 200 ₽. Нормированная цена не заменяет стоимость покупки |
| B03 | Яблоки 139 ₽/кг; нужно 1 кг; минимум 1,5 кг | Минимальный расчёт 1,5 × 139 = 208,50 ₽; возможное отклонение фактического веса оговорено. Без поддержки базы/минимума — отдельный отчёт, не подтверждённый импорт товара |
| B04 | Обычная цена 109 ₽; 103 ₽ от 3 упаковок; нужно 2 | 218 ₽, не 206 ₽. Не записывать скидку как regular |
| B05 | Те же цены; нужно 3 упаковки, все условия выполнены | Ручной расчёт условной цены 309 ₽. Если формат не обеспечивает порог, импортировать только обычные 109 ₽ (327 ₽ без скидки) и отдельно показать 309 ₽ с условиями, не обещать поддержку ступени |
| B06 | После B05 пользователь уменьшает количество с 3 до 2 | Условие перестаёт выполняться; старое подтверждение 103 ₽ недействительно. Перепроверить и вернуть расчёт 218 ₽; условные цены не допускаются к подтверждённому итогу даже с прежним conditionsConfirmed; проверка этого инварианта относится к тестам панели |
| B07 | Цена loyalty известна; карта пользователя неизвестна | `conditionsConfirmed=false`, скидочная цена только справочно. При отдельно подтверждённой обычной цене можно использовать обычную |
| B08 | CAPTCHA до выбора города | `captcha`, scope «Локация не подтверждена», без продуктов этого контекста; не `not_found` и не `unsupported_city` |
| B09 | Сайт загрузился, корректный поиск выполнен и пуст | `not_found` с точным описанием запроса/контекста; отличается от таймаута/error |
| B10 | После двух карточек третья не загружается | Не выдавать частичную выдачу за полный результат; check с причиной для этого контекста, частичные наблюдения отдельно; другие завершённые контексты сохраняют самостоятельный результат |
| B11 | Контекст имеет 60 кандидатов | Не отправлять 40+20 с ожиданием накопления. Отобрать до 40 перед одним вызовом и объявить ограниченный охват |
| B12 | Две последовательные полные порции для одинаковых q/city/store/scope/fulfillment | Более новый снимок заменяет прежний; при переставленных ответах применяется актуальная временная метка и история отказов. Не ожидать суммы кандидатов; проверить фактическое состояние панели |
| B13 | Та же сеть, но другая точка или delivery вместо pickup | Другой контекст; не смешивать в один итог и не считать старый контекст удалённым |
| B14 | Ответ на импорт потерян; неизвестно, принят ли запрос | Статус импорта неизвестен. Проверить панель до повтора; не утверждать успешный импорт или автоматический откат |
| B15 | Новый снимок t2 принят; позже приходит повтор старого t1 | Не повторять старую порцию намеренно; при обнаружении не считать t1 свежим. Панель использует временные метки и историю отказов; t1 не должен отменять t2 даже после перезагрузки/вытеснения кэша. Офлайн-проверка этого пакета не исполняет данный инвариант |
| B16 | Тот же снимок отправлен дважды без нового наблюдения | Сохранить исходный checkedAt; одинаковое наблюдение не становится новым; прогресс определяется актуальным принятым состоянием. Это отличается от UUID-повторов команд списка |
| B17 | Цена упаковки известна, фасовка неизвестна | quantity/unit = null/null; нельзя вычислять число упаковок для запроса в кг/л или подставлять 1 |
| B18 | Товары и check имеют одинаковый контекст в одном payload | Не отправлять: выбрать результат завершённой проверки либо check с причиной; не создавать противоречивый контекст |
| B19 | Все позиции проверены, но доставка неизвестна | Только стоимость продуктов с пометкой «доставка не учтена», не окончательный чек |
| B20 | Акция истекла, или цена известна только из старой рекламы | Не обновлять checkedAt без чтения; не импортировать рекламу как действующее предложение |

## Что проверять в реализации

Эти требования **не расширяют текущий wire-контракт**: валидировать базу цены и ограничения заказа; пересчитывать применимость условий при изменении количества; сохранять защиту от старых снимков; проверять частичные сбои истории отказов/кэша/прогресса и подтверждение применения. Новые команды и связь исследования описаны в [shopping-plan.md](shopping-plan.md) и не опубликованы до отдельного выпуска 0.9.0. До согласования схемы не отправлять дополнительные поля. Выполнять интеграционные проверки только на синтетическом изолированном контексте, не заменяя пользовательские списки.
