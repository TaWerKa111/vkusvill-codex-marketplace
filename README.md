# Корзина · магазины для Codex

Серверный плагин с отдельной панелью: поиск продуктов, корзина, количество, предварительная сумма и ссылка для перехода в магазин. Node.js и локальный сервер не нужны.

[Посмотреть интерактивное демо](https://tawerka111.github.io/vkusvill-codex-marketplace/) · [Исходники сайта и публикация](docs/README.md)

## Установка через Codex

1. Откройте **Plugins → Add plugin marketplace**.
2. В **Source** вставьте `TaWerKa111/vkusvill-codex-marketplace`.
3. В **Git ref** укажите `main`, **Sparse paths** оставьте пустым.
4. Нажмите **Add marketplace** и установите **Корзина · магазины**.
5. [Откройте панель](codex://plugins/vkusvill-cart@vkusvill-cloud/app/cart_browse).

Альтернатива через CLI:

```sh
codex plugin marketplace add TaWerKa111/vkusvill-codex-marketplace --ref main
codex plugin add vkusvill-cart@vkusvill-cloud
```

## Проверка после установки

Откройте панель → «Молоко» → «+» у товара → «Получить ссылку на корзину». Изменение количества сбрасывает устаревшую ссылку. Оформление заказа и оплата выполняются в магазине.

## Как устроено

Каталог содержит манифесты, иконку, общий навык браузерной проверки и 12 навыков сетей. Codex подключается к HTTPS MCP-серверу; он возвращает интерфейс панели и обращается к публичному каталогу ВкусВилла. Панель в Codex вызывает инструменты через хост, а не через прямые браузерные запросы.

Черновик корзины хранится в localStorage панели на устройстве. Поисковые запросы и выбранные идентификаторы/количества передаются серверу и ВкусВиллу для выполнения действий. Приложение не запрашивает пароль, телефон, адрес или банковские данные. Персональные скидки, наличие по адресу и окончательную сумму нужно проверять у магазина.

Независимый проект, не официальный плагин ВкусВилла. Для работы нужен интернет и доступный сервер. Сообщения о проблемах: Issues этого репозитория.

## Исправление установки: 0.3.2

В 0.3.0 основной `mcp.json` не содержал обязательный `$schema`, поэтому Codex мог показывать установленный плагин, не загружая его сервер. В 0.3.2 схема добавлена; файл совместимости `.mcp.json` использует тип `http`. После установки из GitHub проверено реальное появление включённого `vkusvill-cart-cloud` с HTTPS-транспортом в `codex mcp list --json`. Предыдущая проверка статуса установки сама по себе была недостаточной.

Обновление уже установленной версии:

```sh
codex plugin marketplace upgrade vkusvill-cloud
codex plugin add vkusvill-cart@vkusvill-cloud
```

Затем откройте новый чат и выберите «Корзина ВкусВилл · Сервер» через @, либо откройте ссылку панели выше. Если старая панель остаётся открытой, закройте её и откройте снова.

## Версия 0.4.0

Единый список, сравнение ручных цен за единицу и целые упаковки, копирование и перенос товаров между семью магазинами Казани. Неизвестные цены помечаются, итог без доставки. ## Версия 0.5.0

Выбор любого города, района/метро, способа покупки и заметки. Настройки хранятся локально и включаются в копируемый список. Смена города сохраняет товары и введённые цены, но не проверяет наличие или доставку. Район и заметка не передаются магазинам автоматически.


## Версия 0.6.0

«Единый список» → введите продукт → «Сравнить». Цены вводить не нужно: Бахетле (Казань, Павлюхина 57, самовывоз) и публичный ВкусВилл. У ВкусВилла цена по адресу в Казани не подтверждена. Выберите подходящую фасовку; разные бренды не считаются одним SKU. Автоматические цены старше суток или для другого города исключаются из итога. Ручная корректировка остаётся необязательной.

Серверный кэш публичных каталогов — 24 часа, до 500 поисков. Обновление востребованных за последние 7 дней запросов выполняет `prices_refresh`; ошибки не стирают прежнюю цену и дату. Корзины остаются на устройстве.

Кнопка «Проверить через браузер» передаёт задачу агенту Codex. Навык `grocery-prices-browser` проверяет оставшиеся магазины через доступные инструменты браузера. Инструмент `prices_browser_show` возвращает наблюдения в панель, где они сохраняются локально на 24 часа. Они не попадают в общий серверный кэш. Вход, CAPTCHA и недоступность браузера могут потребовать участия пользователя. Фоновая ежедневная проверка личного браузера не включена; компьютер и Codex должны быть доступны.

Это не обещание готовых API всех семи магазинов. Для Пятёрочки проверка обычным браузером 24 октября остановилась на CAPTCHA. Взвешиваемые товары Бахетле пока исключены, поскольку нужно отдельно проверить базу цены.

## Разработка и границы проверки

Этот репозиторий содержит пакет плагина, навыки и статическое демо, но не исходники удалённого MCP-сервера и рабочей панели. Изменение навыка или примера здесь не меняет реализацию серверного инструмента. Версия пакета и версия опубликованного сервера — разные сущности.

- [Реестр возможностей сетей](plugins/vkusvill-cart/skills/grocery-prices-browser/references/stores.md) отделяет документированные сценарии от исторических результатов проверки. Количество сетей в панели не означает количество доступных каталогов или подтверждённых цен.
- [Примеры импорта](plugins/vkusvill-cart/skills/grocery-prices-browser/references/import-examples.json) используют документированные поля текущего контракта. Это тестовые данные, не текущие цены магазинов.
- [Пограничные случаи](plugins/vkusvill-cart/skills/grocery-prices-browser/references/import-cases.md) описывают ограничения расчёта и проверки, которые требуется подтвердить на сервере и в панели.

Локальные проверки пакета требуют только Python 3.10+ и выполняются без запросов к магазинам:

```sh
python3 scripts/validate_repository.py
python3 -m unittest discover -s tests -v
```

Workflow `validate.yml` запускает проверки пакета на pull request и push. Они проверяют согласованность файлов и документированных примеров, но не доказывают доступность MCP, принятие JSON живым сервером, корректность цен, работу localStorage или перенос корзины. Публикация демо остаётся отдельным workflow.

Перед выпуском изменений серверной логики необходимо получить исходники сервера/панели и дополнительно проверить реальное подключение MCP, схемы инструментов, импорт в панели, повторные ответы, смену города/точки/количества и миграцию локальных данных. Исторические 11 тестов версии 0.3.0 не заменяют такую проверку текущего релиза. Изменения в ветке разработки не считаются опубликованным обновлением плагина.
