# Соответствие и стоимость

`exact`: соответствует всем заданным требованиям; для конкретного SKU нужны совпадающие бренд, вариант, состав/жирность и фасовка, по возможности штрихкод. Для широкого «молоко» питьевое молоко может отвечать запросу, сгущёнка — лишь similar. `substitute`: допустимая по запросу замена с явным объяснением отличия. `similar`: похожее, но не подходящее без решения пользователя. `unknown`: данных недостаточно. Не называть разные варианты одним SKU.

Миллилитры перевести в литры, граммы — в килограммы. Граммы молока не переводить в миллилитры. При неоднозначной фасовке quantity/unit = null/null. Для яиц хранить число яиц в упаковке. Для весового товара нормировать цену на указанную базу и сохранить эту базу в condition; не выдумывать размер упаковки.

Число упаковок = ceil(нужное количество / фасовка), итог = число упаковок × цена упаковки. Цены за одну штуку и за коробку не смешивать. Условия «от двух», промокоды, карта, подписка и первая покупка должны быть явно выполнены для планируемого количества; иначе conditionsConfirmed=false. Баллы и кешбэк не вычитать из оплачиваемой суммы. Неизвестная доставка не равна нулю: показывать стоимость продуктов и пометку, что доставка не учтена.

В подтверждённый итог включать только доступные товары с подтверждённой локацией, способом получения, соответствием и применимыми условиями. Разные точки одной сети и способы получения не объединять. Старые акции не обновлять новой датой наблюдения; просроченную рекламу не импортировать как текущую цену. Отсутствие позиции, блокировка и неизвестное наличие имеют разные значения.
